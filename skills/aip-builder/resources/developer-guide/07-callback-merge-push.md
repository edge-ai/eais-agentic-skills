### 3.5. Merge function

The merge function is scheduled at regular intervals (default 1 second,
configurable on the pipeline configuration page). It reads data from the frame
data queue, aggregates the target period, and writes the result to the merge
data queue. Do not depend on merge calls overlapping or being serialized:
runtime scheduling may evolve. Treat each invocation as independent; MS3
preserves publication order. Data older than the pipeline Cache TTL is deleted.

Also, if the merge function does not finish within 5 seconds, it will time out. The name of this function is `merge_and_analyze()`. The arguments of this function are `frame_data_list` and `frame_time_list`. `frame_data_list` is filled with the list of return values ​​of `parse_batch_meta()` read from the queue in chronological order. `frame_time_list` is filled with the list of UNIX time when the return values ​​of `parse_batch_meta()` were generated. Therefore, both lists have the same array length and each element corresponds. The return value of this function can be any Python object, but it must be structured so that it can be converted to JSON format without errors. This return value is fed into the push pipeline via the merge data queue.

Signature: `merge_and_analyze(self, frame_data_list, frame_time_list) -> Any`

Constraints:

- Five-second merge timeout; publication order is preserved
- Do not depend on a particular concurrency model
- Output must be JSON-serializable

#### Helper Methods for Aggregation

```python
import warnings
from collections import defaultdict

@classmethod
def analytics(cls, d):
    for key, value in d.items():
        if isinstance(value, list):
            d[key] = {'max_val': cls.to_int(np.nanmax(value)),
                        'min_val': cls.to_int(np.nanmin(value)),
                        'sum_val': cls.to_int(np.nansum(value))}
    return d

@staticmethod
def aggregate(array, axis=0, logic=None):
    """
    Aggregate Analytics results.
    First, a dictionary of {key: value list} is created for each specified axis.
    Then, the function specified in LOGIC is applied to the value list.
    Finally, a list of appearing keys and their aggregate results is output,
    grouped by specified axis.
    """
    # Adjust dimensions along the axes to make it easier
    # to iterate on other dimensions
    array = np.moveaxis(array, axis, 0)

    key_counts = []
    for slice in array:
        # Aggregate key for each slice of each axis.
        aggregated_keys = defaultdict(list)
        for element in slice:
            if isinstance(element, dict):
                for key, value in element.items():
                    if isinstance(value, int):
                        # Adding values to a key-by-key list.
                        aggregated_keys[key].append(value)

        # Sorting keys
        sorted_dicts = dict(sorted(aggregated_keys.items()))
        # If an aggregation logic is specified, the process
        # is applied to the value list
        if logic:
            sorted_dicts = logic(sorted_dicts)
        # Add to list per axis
        key_counts.append(sorted_dicts)

    return key_counts

@staticmethod
def merge_dicts(*dicts):
    """
    Combine all input aggregate results.
    (Assumption that all dictionary keys in the first
    level of the aggregate result are input source IDs)
    """
    merged_dict = {}
    for d in dicts:
        for key in d.keys():
            if key not in merged_dict:
                merged_dict[key] = {}
            merged_dict[key].update(d[key])
    return merged_dict

@staticmethod
def to_int(value):
    """
    Cast the value to an int. If the value is np.nan, convert to None.
    """
    if value is None or not np.isfinite(value):
        return None
    return int(value)

def merge_and_analyze(self, frame_data_list: List[Any],
                    frame_time_list: List[float]) -> Any:
    """
    A function that is executed periodically at each time interval
    specified in the pipeline configuration.

    frame_data_list: A list of frame data objects generated by the
        `parse_batch_meta` function in chronological order.
    frame_time_list: List of timestamps at which the
        frame data object was created. (Not used in this example.)

    If an error occurs in this function, only the merge will be skipped
    and function execution will resume at the next timing.

    In this example implementation, it takes about 3~5 ms on EX5.
    """
    # Invalid initial batches may have returned empty arrays before initialization.
    if self.first_time or not frame_data_list:
        return {}
    valid_frames = []
    for frame in frame_data_list:
        if (isinstance(frame, np.ndarray) and frame.dtype == self.frame_dtype
                and frame.shape == (self.max_frames_in_batch,)):
            valid_frames.append(frame)
        else:
            self.reject_metadata()
    if not valid_frames:
        return {}
    frame_data_array = np.stack(valid_frames)

    # Aggregation of basic frame information
    basic_info_keys = ['source_id',
                        'frame_number_from',
                        'frame_number_to',
                        'ntp_timestamp_from',
                        'ntp_timestamp_to']
    basic_info = np.concatenate([
        # input source ID
        frame_data_array[[0], :]['source_id'],
        # Minimum and maximum frame number within the period obtained.
        frame_data_array[[0, -1], :]['frame_num'],
        # Minimum and maximum NTP timestamp within the period obtained.
        frame_data_array[[0, -1], :]['ntp_timestamp']
    ], axis=0).T

    # Converting the aggregate results of basic frame information
    # into a dictionary type.
    basic_info_dict = {
        source_id: {
            info_label: self.to_int(basic_info[source_id, info_id])
            for info_id, info_label in enumerate(basic_info_keys)
        }
        for source_id in range(self.max_frames_in_batch)
    }

    # Aggregation of object counters
    obj_counter_keys = ['max_val', 'min_val', 'mean_val', 'median_val', 'count_val']
    obj_counter_list = frame_data_array[:, :]['obj_counter']
    # All-NaN slices are intentional unknowns, preserved as null below.
    with warnings.catch_warnings():
        warnings.filterwarnings("ignore", message="All-NaN slice encountered", category=RuntimeWarning)
        warnings.filterwarnings("ignore", message="Mean of empty slice", category=RuntimeWarning)
        obj_counter_summary = np.stack([
        # Maximum number of class objects in the period obtained
        np.nanmax(obj_counter_list, axis=0),
        # Minimum number of class objects in the period obtained
        np.nanmin(obj_counter_list, axis=0),
        # Average number of class objects in the period obtained
        np.nanmean(obj_counter_list, axis=0),
        # Median number of class objects in the period obtained
        np.nanmedian(obj_counter_list, axis=0),
        # Total number of class objects in the period obtained
        np.where(np.any(np.isfinite(obj_counter_list), axis=0),
                 np.nansum(obj_counter_list, axis=0), np.nan)
        ]).transpose((1, 2, 0))

    # Converting the aggregate results of an object counter to a dictionary type
    obj_counter_summary_dict = {
        source_id: {
            "obj_counter": {
                class_label: {
                    stat_label: (
                        float(obj_counter_summary[source_id, class_id, stat_id])
                        if stat_label in ('mean_val', 'median_val')
                        and np.isfinite(obj_counter_summary[source_id, class_id, stat_id])
                        else self.to_int(obj_counter_summary[source_id, class_id, stat_id])
                    )
                    for stat_id, stat_label in enumerate(obj_counter_keys)
                }
                for class_id, class_label in enumerate(self.pgie_classes or [])
            }
        }
        for source_id in range(self.max_frames_in_batch)
    }

    # Analytics: aggregation of ROI Filtering plugins
    # Aggregate the analysis results for each input source ID and
    # for each ROI label within the obtained time period
    # (maximum, minimum and total values).
    analytics_roi_array = frame_data_array[:, :]['analytics_roi']
    analytics_roi_summary = self.aggregate(
        analytics_roi_array, axis=1, logic=self.analytics)

    # Converting aggregate results of the ROI filtering plugin to dictionary type
    analytics_roi_summary_dict = {
        source_id: {
            "analytics_roi": roi
        }
        for source_id, roi in enumerate(analytics_roi_summary)
    }

    # Analytics: aggregation of Line Crossing plugin
    # Aggregate the analysis results for each input source ID and for each
    # LCC (Line Cross Counting) label within the obtained time period
    # (maximum, minimum and total values).
    analytics_lcc_array = frame_data_array[:, :]['analytics_lcc']
    analytics_lcc_summary = self.aggregate(
        analytics_lcc_array, axis=1, logic=self.analytics)

    # Converting Line crossing plugin aggregate results to dictionary type.
    analytics_lcc_summary_dict = {
        source_id: {
            "analytics_lcc": lcc
        }
        for source_id, lcc in enumerate(analytics_lcc_summary)
    }

    # Combine and output the results of all processed totals.
    # Need to return objects that can be converted to JSON format
    merged_data = self.merge_dicts(
        basic_info_dict,
        obj_counter_summary_dict,
        analytics_roi_summary_dict,
        analytics_lcc_summary_dict
    )

    return merged_data
```

### 3.6. Push function

The push function is executed at regular intervals (default 5 seconds,
configurable on the pipeline configuration page). Data is read from the merge
data queue and sent to Redis Pub/Sub or WebSocket channels together. Data sent
to Redis Pub/Sub can be subscribed to in Node-RED. The destinations can be
specified by the pipeline configuration. This function cannot be edited by AIP
developers.

The message observed by a subscriber depends on the MS3 merge/push
configuration:

- With merge disabled, the probe result is published directly.
- With merge enabled and periodic push disabled, one merge result is published
  directly.
- With both merge and periodic push enabled, multiple merge results are
  published together as time-windowed records containing `since`, `until`, and
  `data`.

Therefore, `merge_and_analyze()` defines the content of one merge result, not
the final Node-RED payload envelope. Inspect a live message before writing a
downstream binding.

### 3.7. Available class variables

AIP developers can use the following class variables defined separately by the system in callback.py. This allows elements that may change depending on the pipeline being executed and the AIP settings to be correctly obtained in callback.py.

- `self.uuid` (str): The ID of the running pipeline.
- `self.pgie_classes` (Optional[List[str]]): List of class names of the primary inference model sorted by class ID. If there is no PGIE, it will be None.
